# Cloud Before Code
## Learn Cloud Computing Through a Business Story

---

### What This Project Is

**Cloud Before Code** is a beginner-friendly, scenario-based curriculum that teaches introductory cloud-computing terminology through one evolving business story. Learners help a fictional food-ordering business, **LunchRush**, solve eight real operational challenges. Each challenge is introduced in plain language before any technical vocabulary is named.

The curriculum is designed as an original teaching resource — not a working application, website, or cloud deployment.

---

### Who It Is For

- Students and nontechnical adults with no prior cloud-computing experience
- Learners who want to understand cloud vocabulary without writing code or creating cloud accounts
- Instructors seeking a ready-to-use, activity-based introductory unit

### How to Run a Lesson

1. **Read the instructor guide** for the lesson you plan to teach (`docs/instructor-guide.md`).
2. **Print or share the learner workbook** pages for that lesson (`docs/learner-workbook.md`). The workbook contains no answer keys.
3. **Gather any materials** listed in the lesson's Materials section (all are paper-based or use editable documents).
4. **Follow the instructor script** in sequence: opening story → exploratory task → terminology → activity → "explain it twice" → exit assessment.
5. **Collect completed worksheets** as learner artifacts.

No software installation, cloud account, or coding is required for any activity.

### What Still Requires Verification or Real Pilot Data

- **Technical definitions** in the instructor guide and learner workbook are marked `[DRAFT — verify against official documentation]`. Cross-check against provider-neutral sources (e.g., NIST SP 800-145, CNCF glossary) and official vendor documentation before teaching.
- **Pre/post-test scores** and pilot feedback tables in `evaluation/` are blank templates. Do not fill them with invented data.
- **Pilot findings** must come from actual volunteers. See `docs/pilot-evaluation-plan.md` for design guidance.
- The **submission proposal** (`docs/submission-proposal.md`) uses future tense for work and evaluation that has not yet occurred.
